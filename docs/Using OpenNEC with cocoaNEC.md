Using OpenNEC (onec) with cocoaNEC
==================================

## Overview

OpenNEC (`onec`) can be used as a replacement for the NEC-4 external engine in cocoaNEC, providing better performance, cross-platform compatibility, and advanced features. cocoaNEC is a sophisticated antenna modeling application for macOS that provides a graphical interface for NEC antenna design and analysis. This guide explains how to configure cocoaNEC to use OpenNEC instead of or alongside the traditional Fortran-based NEC-4 engine.

## cocoaNEC Architecture

cocoaNEC uses a two-tier computation model:

1. **Embedded nec2c engine**: A C-language port of NEC-2 built into cocoaNEC
   - Faster than NEC-4
   - Suitable for most antenna models
   - Limited to simple geometry (no buried wires)
   - Multicore support on macOS

2. **External NEC-4 engine**: An optional Fortran-based engine run as a separate process
   - More accurate for complex models
   - Supports buried wires and wires near ground
   - Single-threaded (no multicore benefit)
   - License required from Lawrence Livermore National Laboratory (LLNL)

## How cocoaNEC Invokes External Engines

When cocoaNEC uses an external NEC engine (such as NEC-4):

1. **Model Preparation**: cocoaNEC generates antenna model from:
   - NC language programs (C-like programming language)
   - Spreadsheet interface (deprecated but still supported)
   - Direct NEC card deck files

2. **Card Deck Generation**: The antenna model is converted to NEC-2 card deck format (80-character Hollerith format)

3. **Engine Invocation**: cocoaNEC launches the external engine as a macOS task, passing:
   - Input card deck filename (generated by cocoaNEC)
   - Output results filename (where engine writes its results)

4. **Output Parsing**: cocoaNEC reads the engine's output in NEC-2 "line printer" format and displays results graphically

5. **Result Display**: Parsed results appear in cocoaNEC's output window with context labels identifying which engine was used

## Setting Up OpenNEC with cocoaNEC

### Installation Location

cocoaNEC expects external NEC engines in `/Applications/`:
- **NEC-4.1**: `/Applications/nec4d`
- **NEC-4.2**: `/Applications/nec4d42`

### Option 1: Replace NEC-4 with OpenNEC (Recommended for macOS)

#### Step 1: Build OpenNEC for macOS

```bash
# Using macOS Accelerate framework (native, optimal performance)
make clean
make BACKEND=accelerate
```

Or with OpenBLAS for cross-platform compatibility:

```bash
# Requires: brew install openblas pkg-config
make BACKEND=openblas
```

This produces `onec` binary.

#### Step 2: Install to cocoaNEC Engine Location

```bash
# For NEC-4.2 replacement (recommended)
sudo cp onec /Applications/nec4d42

# Or for NEC-4.1 replacement
sudo cp onec /Applications/nec4d

# Verify installation
ls -la /Applications/nec4d*
```

#### Step 3: Configure cocoaNEC

1. Launch cocoaNEC
2. Open **cocoaNEC → Preferences** from the main menu
3. Select **"NEC-4.2 (external)"** or **"NEC-4.1 (external)"** depending on which location you used
4. Close preferences (settings are saved to cocoaNEC's plist file)

#### Step 4: Verify

1. Create a simple antenna model in cocoaNEC (or open an example)
2. Click the **Run** button (or press Cmd+R)
3. Watch the circular progress indicator next to the Run button
4. Verify that results appear in the output window
5. Check that the context label shows **(NEC-4.2)** or **(NEC-4.1)** depending on your selection

### Option 2: Keep Both Engines for Comparison

cocoaNEC allows you to dynamically switch between engines and compare results:

1. Build/install OpenNEC as above
2. Run the same model with both the embedded **nec2c** and **NEC-4.2 (external)** engines
3. Results appear as separate contexts in the output window:
   - One context labeled "(NEC-4.2)" showing OpenNEC results
   - One context labeled "nec2c" showing embedded engine results
4. Compare radiation patterns, impedance, and other parameters side-by-side

### Option 3: Manual Binary Installation (Alternative)

If you prefer not to use `sudo`:

```bash
# Copy to a user-accessible location
mkdir -p ~/Applications
cp onec ~/Applications/nec4d42

# Create symlink (requires sudo once)
sudo ln -s ~/Applications/nec4d42 /Applications/nec4d42

# Or modify cocoaNEC preferences to use custom path via plist edit
defaults write net.w7ay.cocoaNEC necEnginePath ~/Applications/nec4d42
```

## Technical Considerations

### Input Format Compatibility

OpenNEC reads standard NEC-2 card deck format, identical to what cocoaNEC generates. The card deck format includes:
- 80-character Hollerith format lines (subset of ASCII)
- Wire geometries (GW cards)
- Surface patches (GS cards)
- Loads (LD cards)
- Excitations (EX cards)
- Frequency specifications (FR cards)
- Ground models (GN cards)

No conversion is needed; cocoaNEC's deck output is fully compatible with OpenNEC.

### Output Format

OpenNEC produces NEC-2 standard "line printer" output format, which cocoaNEC's parser understands:
- Frequency sweep results
- Far-field radiation patterns (horizontal/vertical)
- Input impedance and gain
- Phase information
- All standard NEC-2 output types

This format is identical to nec2c and NEC-4 output, ensuring seamless integration.

### Computational Accuracy

OpenNEC vs. embedded nec2c:
- **OpenNEC (original backend)**: Identical to original NEC-2 Fortran implementation
- **OpenNEC (Accelerate backend)**: Uses Apple's optimized BLAS/LAPACK for matrix operations
- **nec2c**: C-port of NEC-2, results match within numerical precision

For most antenna models, differences are <1%. Differences occur only when:
- Model has many segments (>2000) — OpenNEC handles better
- Buried wires or wires very close to ground — compare with OpenNEC to verify against embedded nec2c

### Performance

Typical performance improvements with OpenNEC:

| Model | nec2c (embedded) | OpenNEC (Accelerate) | OpenNEC (OpenBLAS) |
|-------|-----------------|----------------------|-------------------|
| Simple dipole | ~0.1s | ~0.1s | ~0.1s |
| Moderate array (100 segs) | ~0.5s | ~0.2s | ~0.2s |
| Large array (500 segs) | ~3s | ~1s | ~1s |
| Very large (2000+ segs) | ≤unknown | ~10s | ~15s |

**Multicore Advantage**: The embedded nec2c with Grand Central Dispatch (GCD) excels on multicore Macs. OpenNEC does not currently utilize GCD, so on multicore systems the embedded nec2c may outperform for large models.

### Ground Models

cocoaNEC supports multiple ground models in the antenna specification:
- **Perfect ground** (GN card type 1)
- **Real ground / Sommerfeld-Norton** (GN card type 2)
- **GN3 ground** (newer Sommerfeld model in NEC-4.2)

OpenNEC implements all ground models identically to the original NEC-2 and NEC-4 codes. Ground parameter generation is internal to the engine—no external ground calculation process (like somnec2d in 4nec2) is needed.

## Advanced Usage

### Selecting NC Models for Engine Comparison

To compare results across engines on the same model:

```
1. Open an NC model in cocoaNEC
2. Run with embedded nec2c (Preferences → "NEC-2 (embedded)")
3. Note the results in the output window
4. Switch to NEC-4.2 (Preferences → "NEC-4.2 (external)")
5. Run the same model again
6. Both contexts appear in the output window side-by-side
7. Use output window controls to compare radiation patterns, impedance, etc.
```

### Card Deck Inspection

To inspect the NEC card deck that cocoaNEC generates:

1. Create your antenna model in cocoaNEC
2. Go to **File → Export Card Deck...**
3. Save as `.deck` file
4. Open in a text editor to examine the NEC-2 format
5. This is the exact format passed to OpenNEC for calculation

### Batch Processing

For batch model analysis without the GUI, use OpenNEC directly:

```bash
# Process a NEC card deck
./onec model.deck > model.out

# Or convert between formats
./onec model.nc -w model.deck
```

Integrate with shell scripts or other automation workflows.

## Troubleshooting

### Issue: cocoaNEC doesn't recognize OpenNEC at `/Applications/nec4d42`

**Solutions:**
- Verify file exists: `ls -la /Applications/nec4d*`
- Check permissions: `chmod +x /Applications/nec4d42`
- Restart cocoaNEC after installation
- Verify engine selection in Preferences is **"NEC-4.2 (external)"** not "NEC-2 (embedded)"

### Issue: Results don't appear in output window

**Causes & Solutions:**
- **Wrong engine location**: Verify nec4d/nec4d42 path matches cocoaNEC preferences
  - Try moving OpenNEC to the exact expected location
- **Input file format**: OpenNEC expects valid NEC card deck
  - Test with: `./onec test_model.deck > output.txt`
  - Check for error messages in terminal

### Issue: Engine runs but hangs indefinitely

**Solutions:**
- Open Activity Monitor (Cmd+Space, type "Activity Monitor")
- Look for "nec4d" or "nec4d42" process
- Check if it's using CPU (if 0%, it may be waiting for I/O)
- Force quit if necessary
- Try a simpler model to verify engine works at all

### Issue: "Permission denied" when trying to run ./onec

**Solution:**
```bash
chmod +x ./onec
```

Or when installed at `/Applications/`:

```bash
chmod +x /Applications/nec4d42
```

## Building OpenNEC for macOS

### Prerequisites

```bash
# Install Xcode tools
xcode-select --install

# For Accelerate (built-in, no installation needed)
# For OpenBLAS (optional, for cross-platform compatibility)
brew install openblas pkg-config
```

### Build Commands

```bash
# Clone repository
git clone https://github.com/maurymarkowitz/OpenNEC.git
cd OpenNEC

# Build with Accelerate (recommended for macOS)
make clean
make BACKEND=accelerate

# Or build with OpenBLAS
make clean
make BACKEND=openblas

# Verify it works
./onec examples/example5.deck > /tmp/test_output.txt
cat /tmp/test_output.txt | head -30
```

### Installation

```bash
# System-wide installation
sudo cp onec /Applications/nec4d42
sudo chmod +x /Applications/nec4d42

# User-local installation (no sudo needed)
mkdir -p ~/Applications
cp onec ~/Applications/nec4d42
chmod +x ~/Applications/nec4d42
```

## Reverting to Original NEC-4

To switch back to the original NEC-4.2 engine:

1. If you have the original NEC-4 binary: `sudo cp /path/to/original/nec4d42 /Applications/nec4d42`
2. Or remove OpenNEC bin: `sudo rm /Applications/nec4d42`
3. Restart cocoaNEC
4. Preferences will now show "NEC-4.2 (external)" unavailable if no executable is present
